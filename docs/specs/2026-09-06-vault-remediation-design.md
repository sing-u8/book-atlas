# 볼트 교정 설계 — PDF 교체 이후 재검수와 일괄 수정

작성일 2026-09-06 · 대상 볼트 `designing-llm-applications-atlas` · 대상 스킬 `book-atlas`

## 1. 배경

이 볼트는 **쓸 수 없는 PDF** 로 작성됐다. 2026-09-05 에 교체됐고, 두 판본의 성격이 다르다.

| | 옛 PDF (폐기) | 새 PDF (현재) |
|---|---|---|
| 쪽 매김 | 인쇄 쪽번호 없음 → 오프셋 0 으로 가정 | 인쇄 쪽번호 있음 → **오프셋 22** (`verify-offset.sh` 표본 8/8) |
| 분량 | 리플로우 확대판, 실제의 약 1.9배 | 367쪽 완전판 (13장 + 색인) |
| 코드·표 | 가로로 잘려 렌더 — 오른쪽 소실 | 온전 |

같은 판본임은 원서 오탈자 8종(`bitsnbytes`·`Loshcilov`·`Kullback-Liebler`·`OpenAi`·`ensemnle`·
`Tramer er al`·`Pegasus PaLM`·`mostly fiction`)이 양쪽에 모두 있음으로 확인했다. 내용이 바뀐
개정판이 아니라 **같은 책의 온전한 렌더**다.

세 가지 결과가 따라온다.

1. **쪽 인용이 전부 무효다.** `pages:` 125개 · 본문 `p.NNN` 315개 · `_coverage.md` 135행 = 575곳.
   옛 판본이 리플로우판이라 단순 가감으로 변환되지 않고 절마다 새로 찾아야 한다.
2. **"원문이 잘려 있다"는 고지가 사실이 아니다.** 책은 멀쩡했고 그 PDF 가 잘렸다.
   잘린 자리를 노트가 임의로 메운 곳은 실제 원문과 어긋나 있다.
3. **분할 구조가 유령 쪽수로 결정됐다.** 1~7장 자식 노트 77편이 그 판정의 산물이다.

## 2. 목표 / 비목표

**목표**
- 1~7장을 새 판본 기준으로 재검수하고, 발견을 **누락 없이** 수정한다.
- 누락 여부를 사람의 기억이 아니라 **기계가 판정**한다.
- 같은 결함이 8~13장에서 재발하지 않도록 스킬 게이트를 보강한다.

**비목표**
- 8~13장 정리(아직 시작 안 함).
- 볼트의 서술 스타일·번역 품질 개선. 원문 충실성만 다룬다.
- 그래프 뷰어·용어집 스키마 변경.

## 3. 원장

### 3.1 위치

```
{vault}/_global/fixes/
  ch01.md … ch07.md     장별 원장 — 그 장 담당 에이전트만 쓴다
  cross-chapter.md      용어집 · 모호한 위키링크 · 장을 넘나드는 상호참조 — 주 세션만 쓴다
  skill.md              book-atlas 게이트 보강 — 주 세션만 쓴다
```

`_global/` 은 이미 설정 영역이라 학습 자료를 어지럽히지 않고, 볼트와 함께 남아 세션이 끊겨도 살아남는다.

### 3.2 자족성 원칙

**원장의 한 행은 자족적이다.** 감사 보고서·이 명세·대화 기록을 참조하지 않고, 맥락이 없는
에이전트가 그 행만 읽고 수정을 실행할 수 있어야 한다. `근거` 필드에 원문을 인용해 두는 이유가
이것이다 — 실행자가 PDF 를 다시 열지 않아도 된다.

### 3.3 행 형식

````markdown
### CH01-014 · G · 05-prompting
- **무엇** 저자의 프롬프팅 학습론 문단이 통째로 빠졌다
- **근거** 책 p.17 (PDF 39) — "I recommend Learn Prompting's prompting guide in
  particular… Most of what you need to know about prompting can be learned in a
  couple of hours. What matters more is interacting with the LLMs you use
  frequently… We will learn more prompting nuances in Chapters 5 and 13."
- **조치** 「본문 정리」의 프롬프트 엔지니어링 논지 뒤에 문단 추가 — Learn Prompting
  가이드 추천 · "두어 시간이면 배우고, 중요한 건 자주 쓰며 출력을 관찰해 직관을 기르는 것" ·
  5장·13장 상호참조.
- **검증** `grep -q "Learn Prompting" 05-prompting.md && grep -q "13장" 05-prompting.md`
- **상태** 열림
````

헤더는 `### {ID} · {단계} · {대상}` 고정. 본문은 `- **{키}** {값}` 다섯 줄 고정.
값이 여러 줄이면 이어지는 줄을 들여쓴다.

`{대상}` 과 검증식의 실행 위치는 ID 종류에 따라 다르다.

| ID 종류 | `{대상}` | 검증식 실행 위치 |
|---|---|---|
| `CH{NN}-` | 노트 basename (확장자 없이) | 그 노트가 있는 챕터 디렉터리 |
| `XC-` | 대상 파일 하나면 그 이름, 여럿이면 `다수` (조치에 열거) | 볼트 루트 |
| `SKILL-` | 스킬 저장소 기준 파일 경로 | 스킬 저장소 루트 |

### 3.4 필드 규약

| 필드 | 규약 |
|---|---|
| ID | `CH{NN}-{NNN}` 장별 일련. 장 넘나듦 `XC-{NNN}`, 스킬 `SKILL-{NNN}`. **한 번 부여하면 바뀌지 않는다** |
| 단계 | `S` 구조 · `P` 쪽 · `K` 스킬 · `E` 오류 · `G` 보완필요 · `M` 사소 |
| 무엇 | 한 문장. 결함의 진술 |
| 근거 | `책 p.N (PDF p.M)` + **원문 인용**. 그림이면 `Figure N-M` 과 실측값 |
| 조치 | 어느 노트 어느 자리에 무엇을. "감사 보고 참조" 금지 |
| 검증 | 종료코드 0 이면 적용됨. 실행 위치는 §3.3 의 ID 종류별 표를 따른다 |
| 상태 | `열림` → `적용` → `검증`. 또는 `보류(사유)` |

### 3.5 검증식 작성 규칙

- **추가형** — 존재 확인. `grep -q "넣을 문구" 노트.md`
- **제거형·정정형** — 부재 확인. `! grep -q "틀린 문구" 노트.md`
- **교체형** — 둘 다. `! grep -q "옛것" f.md && grep -q "새것" f.md`
- 어느 형태로도 안 되면 `- **검증** 수동` 으로 적는다. **숨기지 않는다** —
  `reconcile.sh` 가 수동 검증 행을 따로 세어 보고한다.

## 4. 단계 순서

의존 관계가 있어 순서를 바꾸면 작업이 중복된다.

| 단계 | 내용 | 이 자리인 이유 |
|---|---|---|
| **0** | 2~7장 재검수 (1장 완료) | 원장 행을 생산한다 |
| **1 · S** | 구조 재적용 — 병합·개명·링크 재연결 | 뒤의 모든 행이 참조할 파일명을 바꾼다 |
| **2 · P** | 쪽 재기준화 575곳 | 병합으로 구간이 합쳐진 뒤라야 최종 범위가 확정된다 |
| **3 · K** | 스킬 게이트 보강 + 수용 시험 | 실제 쪽이 있어야 범위 구멍 검사가 작동한다. **여기서 새 누락이 나와 E·G 행이 늘 수 있다** |
| **4 · E → G** | 오류 → 보완필요 | 내용 수정 |
| **5 · M** | 사소 | 분리 단계. 중단해도 실질 품질은 확보된 상태 |
| **6** | 전 장 게이트 + `reconcile.sh` + 그래프 재빌드 | 최종 검증 |

K 를 E·G 앞에 두는 이유: 보강된 게이트가 찾아내는 구멍은 **언제 돌리든 같은 개수**다. 뒤에 두면
이미 닫은 노트를 다시 열어 두 번째 내용 수정 라운드를 돌아야 한다. 앞에 두는 것은 작업을 늘리는
것이 아니라 앞당겨 드러내는 것이고, 총량으로는 줄어든다.

## 5. 소유권과 상태 전이

- 장별 원장 `chNN.md` 는 **그 장 담당 에이전트만** 쓴다. `cross-chapter.md`·`skill.md` 는 주 세션만 쓴다.
- 재검수 에이전트는 **자기 장 원장 파일만** 쓸 수 있다. 볼트 노트 수정은 여전히 금지 —
  재검수 규약의 "어떤 파일도 수정하지 마라"에 이 예외 하나만 뚫는다.
- 에이전트는 상태를 **`적용` 까지만** 올릴 수 있다. **`검증` 은 `reconcile.sh` 만 쓴다.**
  에이전트가 완료를 보고해도 검증식이 실패하면 그 행은 닫히지 않는다.

## 6. 도구

두 스크립트 모두 `{vault}/_global/fixes/` 에 두고, 종료코드 계약은 기존 검사 스크립트와 같다 —
**0 통과 · 2 검사 실패 · 1 사용법·입력 오류**.

### 6.1 `lint-ledger.sh <원장파일|디렉터리>`

형식 검사. 다음을 잡는다.

- 헤더가 `### {ID} · {단계} · {대상}` 형태가 아님
- 필수 필드 5개(`무엇`·`근거`·`조치`·`검증`·`상태`) 누락
- ID 중복 (파일 간 포함)
- 단계 태그가 `S|P|K|E|G|M` 이 아님
- 상태가 `열림|적용|검증|보류(...)` 가 아님
- 검증식이 `bash -n` 구문 검사를 통과하지 못함
- `조치` 에 "감사 보고 참조" 류 문구가 있음 (자족성 위반)

### 6.2 `reconcile.sh [원장파일|디렉터리]`

각 행의 검증식을 §3.3 이 정한 위치에서 실행하고 집계한다.

```
열림                N건
적용 · 검증 통과     N건   → 상태를 '검증' 으로 승격
적용 · 검증 실패     N건   ← ID 와 함께 전부 나열
수동 검증 필요       N건   ← ID 와 함께 전부 나열
보류                N건   ← 사유와 함께 나열
```

`적용 · 검증 실패` 또는 `열림` 이 하나라도 있으면 종료코드 2.

## 7. S단계 — 구조 재적용 판정

### 7.1 판정 절차 (장마다)

1. 새 PDF 의 임베드 아웃라인에서 그 장의 **최하위 항목** 집합을 뽑는다.
2. 현재 자식 노트 하나하나에 대해:
   - **아웃라인 항목에 대응하면 → 유지.** (`toc-pipeline.md` §9: 목차 subsection 은 그 자체로 노트 하나이며 분할·병합 절차의 대상이 아니다)
   - 대응하지 않으면 → 그 자리에 **본문 표제가 실재하는지** 확인한다. 실재하면
     자체 하위 제목이므로 **분할 유지**, 없으면 **부모로 병합**.

3. 얇은 항목 병합 규칙을 재적용한다 — 2책쪽 이하 **그리고** 자체 도표 없음 **그리고** 독립
   메커니즘 아님. 규칙의 단서대로 **애매하면 독립 노트로 둔다**.

> **아웃라인에 없다고 곧바로 병합 대상이 아니다.** 새 PDF 의 아웃라인은 옛 것보다 얕아,
> 책 본문에 표제로 찍혀 있는데 북마크에는 없는 항목이 있다(예: `Extracting Text from Raw Web
> Documents`, `Bottleneck adapters`, `Normalization`). 이들은 저자가 나눈 단위이므로 자체 하위
> 제목으로 간주해 분할을 유지한다. 결과적으로 병합 대상은 **아웃라인에도 없고 본문 표제도 없는**
> 자식뿐이다.
>
> **본문 표제 판정 방법.** 그 절 구간을 `pdftotext -layout` 으로 뽑아, 짧고·마침표가 없고·좌측
> 정렬된 독립 줄을 후보로 삼는다. 본문 문장과 구분이 애매하면 `pdftoppm` 으로 그 쪽을 렌더해
> 서체로 판정한다. 판정 근거를 S행의 `근거` 필드에 남긴다.

### 7.2 쪽수 조건의 강등

기존 규칙의 "6책쪽 초과" 는 근거 없는 상수였고, 이 책에서는 한 번도 단독으로 작동하지 않는다.
측정 결과 절 202개(길이가 1쪽 이상인 것 171개)의 중앙값 1쪽·평균 1.9쪽이고 6쪽을 넘는 절은 둘뿐인데(LLM Evaluation 7쪽,
Guardrails and Verifiers 8쪽) **둘 다 저자의 하위 제목을 갖고 있어** 하위 제목 조건에 이미 걸린다.

따라서 자동 트리거에서 빼되 지우지는 않고 **점검 신호**로 강등한다:

> 그 책 절 길이 분포의 상위 5% 를 넘는데 자체 하위 제목이 없으면, 쪼갤 자연 경계가 정말 없는지
> 본문을 확인하고 판단 근거를 `_coverage.md` 에 남긴다.

절대 상수가 사라지고 책마다 계산되며, 자동으로 쪼개지 않고 사람이 보게만 한다.
(`toc-pipeline.md` §9 를 이 문구로 고치는 것은 `K` 단계의 `SKILL-` 행이다.)

### 7.3 병합 한 건의 파생 작업

S행 하나의 `조치` 에 아래를 전부 적는다.

- 자식 노트 내용을 부모의 H3 으로 흡수 (부모는 껍데기 금지 규칙을 계속 지킨다)
- 자식 파일 삭제
- 볼트 전역에서 `[[자식]]` → `[[부모#H3제목]]`
- `_glossary.md` 의 해당 용어 "처음 나온 곳" 갱신
- `_coverage.md` 의 정리 노트 칸과 `_chapter.md` 의 링크·mermaid 갱신

### 8.2 왜 연속성 검사만으로는 부족한가

이번 감사에서 가장 무거웠던 세 누락을 `_coverage.md` 와 대조하면 전부 같은 성격이다.

| 5장 WARNING 반 쪽 | `279–280` (03-loading-llms) **안** | 선언됨, 노트에 없음 |
| 7장 모델 융합 전환 문장 | `371(14행)–375(11행)` (03a) **안** | 선언됨, 노트에 없음 |

(쪽 표기는 폐기된 판본 기준. 실제 위치는 각각 책 p.82 · p.137 · p.188)

셋 다 **선언은 돼 있는데 노트가 담지 않은 것**이다. 연속성 검사는 "행이 없는 구간"을 잡으므로
이 셋을 하나도 못 잡는다. 그래서 SKILL-001b 인도 검사를 함께 둔다.

### 8.3 수용 시험

**SKILL-001 (연속성, FAIL)** — 시험용으로 `_coverage.md` 행 하나를 지우면 그 구간을 구멍으로
보고해야 하고, 지우지 않은 상태에서는 1~7장 전부 통과해야 한다.

**검출 신호는 들여쓰기다.** 이 책의 콜아웃 박스에는 `WARNING`·`NOTE` 같은 **텍스트 라벨이 없다**
(아이콘으로 표시돼 텍스트 레이어에 안 남는다 — 전 책 grep 0건). 대신 `pdftotext -layout` 출력의
왼쪽 여백이 층을 이룬다.

| 들여쓰기 | 정체 |
|---:|---|
| 0칸 | 본문. 짧고 마침표 없는 독립 줄이면 **표제** |
| 4~6칸 | 코드·프롬프트 예제 |
| 15칸 이상 | **콜아웃 박스·사이드바** (실측: 책 p.8 은 22칸, p.82 사이드바 제목 29칸, p.136 은 17칸) |

**SKILL-001b (인도, WARN)** — 아래 둘을 **반드시 목록에 올려야** 한다.

- 5장 — 책 p.137 (PDF 159) 상단 WARNING "Do not trust evaluations performed by GPT-4 or any
  other LLM…" 이 `03-loading-llms` 의 선언 구간 안인데 그 노트에 없음 → **콜아웃 검출로 잡힘**
- 3장 — 책 p.82 (PDF 104) 의 본문 표제 `Postprocessing` 이 `03e-wordpiece` 의 선언 구간 안인데
  그 노트에 없음 → **본문 표제 검출로 잡힘**

**기계로 잡히지 않는 것도 명시한다.** 7장 책 p.188 의 전환 문장은 콜아웃도 표제도 캡션도 아닌
평범한 산문이라 어떤 휴리스틱으로도 걸리지 않는다. 이런 유형은 게이트가 아니라 사람이 읽어야
찾는다 — 인도 검사의 한계로 문서에 남긴다.

**잡음 상한.** 인도 검사가 한 장에서 30건을 넘게 내놓으면 손으로 분류할 수 없어 쓸모가 없다.
그 경우 **후보 검출 자체를 좁힌다** — 들여쓰기 임계를 올리거나 표제로 인정하는 조건(길이·형태)을
조인다. 두 번 조여도 30건 아래로 안 내려가면 이 검사를 **보류**한다.

> **조이는 방법을 틀리게 적었던 것을 바로잡는다.** 처음에는 "탐침에서 흔한 단어를 더 뺀다" 고
> 적었는데, 그것은 **합계를 줄일 수 없다** — 탐침을 빼면 항목이 `언급됨` 에서 `누락 의심`·
> `확인 불가` 로 옮겨갈 뿐 후보 개수 자체는 그대로다. 실측으로 확인됐다(조인 뒤 오히려 늘었다).
> 합계를 줄이려면 **후보를 덜 검출**해야 한다.

> **측정 시점.** 이 상한은 `_coverage.md` 의 쪽번호가 **P 단계에서 실제 판본 기준으로 재기준화된
> 뒤에만** 의미가 있다. 낡은 쪽번호에 오프셋을 적용하면 전혀 다른 장의 원문을 뽑아오므로
> (실측: 5장이 선언한 "책 p.279" 가 새 판본에서는 11장 Chunking 이다) 검사는 정확히 동작해도
> 숫자는 무의미하다. **따라서 상한 판정은 K 단계가 아니라 P 단계 완료 후에 한다.**
