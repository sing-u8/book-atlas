# 파일 템플릿

이 스킬이 만들거나 사용자가 유지하는 모든 파일 구조. `{book-slug}-atlas/` 안에
파일을 하나라도 쓰기 전에 이 문서를 먼저 읽는다.

본문 산문(용어집 정의, 노트 프로즈 등)은 사용자가 쓰는 언어를 따른다. 예외는
절 노트·`_chapter.md` 의 필수 H2 헤딩과 구분자 문자열이다 — `check-note.sh` 가
이들을 리터럴 문자열로 대조하므로 사용자 언어와 무관하게 항상 고정 한국어다.
파일명·슬러그는 grep·Obsidian 호환을 위해 언제나 영어 kebab-case.

---

## 저장소 뼈대

```
{book-slug}-atlas/
├── _global/
│   ├── config.md
│   └── source-manifest.md
├── _glossary.md
├── _assets/
├── graph/
│   ├── graph.html
│   ├── graph-data.js
│   └── lib/3d-force-graph.min.js
├── [part-N-{slug}/]                # 책에 Part 가 있을 때만
│   └── chapter-NN-{slug}/
│       ├── _chapter.md
│       ├── _coverage.md
│       └── NN-{slug}.md            # 하위 항목은 NNa-, NNb-
```

전체 계약(디렉터리 명명 규칙·챕터 디렉터리 선제 생성 등)은
`docs/specs/2026-08-31-book-atlas-design.md` §2 가 정본이다. 아래는 그 파일들
각각의 내부 형식이다.

---

## ① `_global/config.md`

### 무엇을 쓰는가

| 필드 | 의미 |
|---|---|
| `book_slug` | 책 식별 슬러그 — 그래프 노드 id(`book:{slug}`)와 저장소 이름(`{slug}-atlas/`)에 쓰인다 |
| `book_title` | 책 제목 — 그래프 book 노드의 라벨 |
| `language` | 대화·파일 본문 언어 |
| `vault_name` | Obsidian vault 이름 — 그래프 클릭 시 `obsidian://` URI 에 그대로 들어간다 |
| `source_pdf` | 원서 PDF 경로 (vault 기준 상대경로) |
| 진행 위치 표 | 챕터별 상태(`진행 중`/`완료`)·다음에 정리할 절 |

`vault_name` 은 온보딩 때 사용자에게 **직접 묻는다** — 자동 추정하지 않는다.
틀리면 그래프의 모든 클릭이 조용히 실패하기 때문이다. 비워 두면 뷰어는 클릭 시
정보 패널만 연다.

### 예시

```markdown
# Config

## 기본
- book_slug: sample-book
- book_title: Sample Book
- language: ko
- vault_name: TestVault
- source_pdf: ../sample.pdf

## 진행 위치
| 챕터 | 상태 | 다음 |
|---|---|---|
| chapter-01-intro | 진행 중 | 02-ranking |
```

**소유권**: 스킬 소유 — 온보딩 때 스킬이 쓰고, 정리 세션마다 진행 위치 표를
스킬이 갱신한다.

---

## ② `_global/source-manifest.md`

### 무엇을 쓰는가

| 구성 | 의미 |
|---|---|
| 소스 | `book_slug`·`book_title`·`pdf` 경로 |
| 쪽 오프셋 표 | `PDF쪽 = 책쪽 + 오프셋`. 삽지·Part 표지·컬러 도판이 끼면 오프셋이 책 중간에서 바뀌므로 단일 값이 아니라 구간별 표로 기록한다 |
| 목차 트리 표 | `계층 · 번호 · 제목 · 슬러그 · 시작 책쪽 · 상태` |

상태값 3종:

| 값 | 의미 |
|---|---|
| `파싱됨` | 목차 추출 단계에서 정상 인식됐다 |
| `미파싱` | 추출 실패했거나 확신이 낮다. 전체 실패로 보지 않는다 — 그 챕터에 실제로 도달했을 때 사용자에게 한 번 묻는다 |
| `사용자수정` | 사용자가 이 행을 손으로 고쳤다는 표시. 스킬은 이 행을 재파싱 결과로 **덮어쓰지 않는다** |

### 예시

```markdown
# Source Manifest

## 소스
- book_slug: sample-book
- book_title: Sample Book
- pdf: ../sample.pdf

## 쪽 오프셋
| 구간 | 오프셋 | 검산 |
|---|---|---|
| Ch.1–2 | 8 | 왕복 3/3 일치 |

## 목차 트리
| 계층 | 번호 | 제목 | 슬러그 | 시작 책쪽 | 상태 |
|---|---|---|---|---:|---|
| chapter | 1 | Intro | chapter-01-intro | 1 | 파싱됨 |
| section | 1 | What Is Retrieval | 01-what-is-retrieval | 2 | 파싱됨 |
| section | 2 | Ranking | 02-ranking | 5 | 파싱됨 |
| chapter | 2 | More | chapter-02-more | 9 | 파싱됨 |
| section | 1 | Advanced | 01-advanced | 10 | 파싱됨 |
```

**소유권**: 정본 — 스킬이 쓰지만 최종 권한은 사용자에게 있다. 스킬은 매 세션
시작에 이 파일을 다시 읽되, `사용자수정` 행은 재파싱 제안 대상에서 제외한다.

## ③ 절 노트 `NN-{slug}.md`

한 절을 다루는 노트 한 장. 구분자 위(frontmatter + 6개 H2)는 스킬이 쓰고,
구분자 아래는 사용자 영역이다.

### frontmatter 7키 — 그래프 빌더가 파싱하는 계약

| 키 | 의미 |
|---|---|
| `book` | `config.md` 의 `book_slug` 와 일치 |
| `chapter` | 챕터 디렉터리명 (Part 접두는 제외, 마지막 한 칸만) |
| `section` | 목차 번호(사람용). 예: `"1.1"` |
| `title` | 원문 제목 |
| `pages` | 사람용 표기 `"책 p.x–y / PDF p.a–b"` — 빌더는 존재만 확인한다 |
| `concepts` | 이 절이 **중요하게 다루는** 개념 슬러그 배열 → 그래프 `covers` 엣지. 각 슬러그는 `_glossary.md` 등재 항목이어야 한다(`check-note.sh` 가 대조) |
| `status` | `draft` \| `done` |

`concepts:` 와 본문의 `[[링크]]` 는 역할이 다르다 — 전자는 "중요하게 다룸"(굵은
엣지 `covers`), 후자는 "언급"(얇은 엣지 `mentions`).

### 필수 H2 6개 — 기계 검사 리터럴, 로컬라이즈하지 않는다

| 섹션 | 내용 |
|---|---|
| `## 한눈에 보기` | 질문 → 핵심 답 표 1개. 항목 나열이 아니라 이 절이 답하는 질문을 세운다 |
| `## 왜 이 절인가` | 정의로 열지 않는다 — 구체적 장면·코드·숫자에서 출발해 이 절의 문제의식으로 |
| `## 본문 정리` | 원문 하위 제목을 H3 로 미러링하며 재구성 정리 |
| `## 개념` | 이 절에서 처음 등장한 개념 표: 개념 · 한 줄 정의 · `[[_glossary#슬러그]]` 링크 |
| `## 연결` | `- [[대상]] — 관계의 성격 한 줄` 형식 ≥2. 대상은 다른 절 노트 또는 개념 |
| `## 스스로 확인` | 답 없는 씨앗 질문 2~3개 |

도표는 섹션이 정해져 있지 않다 — 노트 어딘가에 `mermaid`/`text` 코드펜스 또는
`![[_assets/...]]` 임베드가 **최소 1개** 있으면 된다(존재 검사).

처음 등장하는 전문어는 본문에서 `**[[슬러그]]**(= 한 줄 풀이)` 형태로
링크+풀이를 함께 붙이고 용어집에 등재한다. 이미 다른 절에서 먼저 소개된
용어라면 재등장 시 풀이 없이 `[[슬러그]]` 로만 링크한다.

### 예시 — `chapter-01-intro/01-what-is-retrieval.md`

이 예시는 `scripts/tests/fixtures/vault/chapter-01-intro/01-what-is-retrieval.md`
와 **바이트 단위로 동일**하다 — 테스트 픽스처의 통과 케이스가 곧 이 문서의
예시다.

````markdown
---
book: sample-book
chapter: chapter-01-intro
section: "1.1"
title: "What Is Retrieval"
pages: "책 p.2–4 / PDF p.10–12"
concepts: [retrieval]
status: done
---

# 1.1 What Is Retrieval

## 한눈에 보기

| 질문 | 핵심 답 |
|---|---|
| 검색이 왜 생성보다 먼저 오나? | 모델이 모르는 문서를 먼저 찾아야 답할 재료가 생기기 때문 |

## 왜 이 절인가

사내 위키 1만 페이지에서 휴가 규정을 찾는다고 하자. 질문을 모델에 그냥 던지면
위키를 학습한 적 없는 모델은 지어내기 시작한다 — 그래서 관련 문서를 먼저 찾아
오는 **[[retrieval]]**(= 질문과 관련된 문서를 먼저 찾아오는 단계)이 필요해진다.

## 본문 정리

### 검색이 먼저다

책은 사내 위키 예시를 든다. 질문을 받으면 먼저 관련 문서를 찾는다 — 모델이
학습하지 않은 정보를 답에 쓰기 위해서다. 찾은 문서는 **[[context]]**(= 모델에
함께 넣어 주는 참고 자료)로 붙는다.

```mermaid
flowchart LR
    Q[질문] --> R[retrieval] --> C[context] --> A[답변]
```

## 개념

| 개념 | 한 줄 정의 | 링크 |
|---|---|---|
| retrieval | 질문과 관련된 문서를 먼저 찾아오는 단계 | [[_glossary#retrieval]] |
| context | 모델에 함께 넣어 주는 참고 자료 | [[_glossary#context]] |

## 연결

- [[02-ranking]] — 여기서 찾아온 문서를 다음 절이 순위 매긴다
- [[context]] — retrieval 의 산출물이 context 로 들어간다

## 스스로 확인

- retrieval 없이 모델만으로 답할 때 무엇이 먼저 깨지나?
- context 가 커질수록 무엇이 나빠지나?
````

## ④ `_chapter.md`

챕터 개요. deep-tutor 챕터 `_map.md` 의 정리 중심 버전이며, 책 모드와 마찬가지로
**스킬이 쓴다.**

### 무엇을 쓰는가 — 필수 요소 5개

| 요소 | 내용 |
|---|---|
| 1. 장의 논지 | "이 장은 기능 목록이 아니라 ~라는 하나의 흐름을 이해하는 장이다" 한 문단 |
| 2. 읽는 순서 | 노트 사이 의존 순서를 보여주는 mermaid flowchart |
| 3. 노트 → 질문 표 | 각 노트가 원문의 어느 질문에 답하는지 |
| 4. `[[_coverage]]` 링크 | 누락 추적은 커버리지 파일이 담당한다는 문장 |
| 5. 구분자 + `## 내 메모` | 절 노트와 동일한 사용자 영역 |

챕터 정리를 시작할 때 뼈대(1·2·3 은 비어 있을 수 있음)를 만들고, 챕터 완결
시점에 1~3 을 완성한다. deep-tutor 의 "재구성 대조" 절은 두지 않는다 — 이
스킬은 인출 훈련을 하지 않는다.

### 예시

````markdown
# Chapter 1. Intro

이 장은 기능 목록이 아니라 **왜 생성 전에 검색이 오는가**라는 하나의 흐름을
이해하는 장이다 — 문서를 찾아오는 단계([[01-what-is-retrieval]])와 그것을
추려서 줄 세우는 단계([[02-ranking]])가 어떻게 이어지는지를 본다.

## 읽는 순서

```mermaid
flowchart LR
    A[01-what-is-retrieval] --> B[02-ranking]
```

## 노트 → 원문 질문

| 노트 | 원문에서 답하는 질문 |
|---|---|
| [[01-what-is-retrieval]] | 검색이 왜 생성보다 먼저 오는가? |
| [[02-ranking]] | 찾아온 문서를 그대로 다 쓰면 안 되는 이유는? |

원문 커버리지 전체는 [[_coverage]] 에서 확인한다.
````

구분자 아래 `## 내 메모` 는 사용자 소유.

## ⑤ `_coverage.md`

챕터마다 하나. `check-note.sh` 는 노트 한 장이 노트답게 생겼는지만 보고 원문의
일부만 담아도 통과시킨다 — 이 파일이 그 빈틈을 메운다. **작성 시점이 핵심**이다:
챕터를 다 쓴 뒤가 아니라 **시작할 때** 표 1 의 왼쪽 세 열을 먼저 채운다. 아직
`정리 노트` 가 빈 행이 그대로 할 일 목록이 된다.

### 무엇을 쓰는가

**표 1 — 원문 절 → 노트 매핑**

| 열 | 내용 |
|---|---|
| 책 쪽 | 목차 기준 책 쪽 범위 |
| PDF 쪽 | `source-manifest.md` 오프셋을 적용한 결과 |
| 원문 절 | 그 범위가 다루는 것을 한 줄로 |
| 정리 노트 | `[[NN-slug]]` 위키링크. 여러 개면 나열, 없으면 `—` |
| 상태 | 아래 상태값 참고. **마지막 열 헤더가 `상태`인 표**를 `check-chapter.sh` 가 찾는다 |

**표 2 — 코드·예제 커버리지**

| 열 | 내용 |
|---|---|
| 원문 예제 | 코드 조각·명령·설정 |
| 노트 | `[[NN-slug]]` |
| 설명 보강 | 책이 안 쓴 것 중 노트가 더한 것 |

**상태값**: `반영`(온전히 담김) / `부분`(일부만 담김) / `미반영`(담기지 않음).
`check-chapter.sh` 는 상태 칸이 값 하나만 있고 뒤에 아무 사유도 없으면 실패시킨다
— `부분`·`미반영` 뒤에는 반드시 `— 사유` 형식으로 이유를 붙인다. `반영` 은
사유가 필요 없다.

**병합 행 규칙**(§7 분할·병합): 절이 부모 노트에 병합돼도 표의 행은 지우지
않는다 — `정리 노트` 칸이 흡수한 부모 노트를 가리키게 고친다. 예:

```markdown
| 8 | 16 | Minor Aside (병합됨) | [[01-what-is-retrieval]] | 반영 |
```

### 예시

```markdown
# Chapter 01 원문 커버리지

## 1. 원문 절 → 노트 매핑
| 책 쪽 | PDF 쪽 | 원문 절 | 정리 노트 | 상태 |
|---|---|---|---|---|
| 2–4 | 10–12 | What Is Retrieval | [[01-what-is-retrieval]] | 반영 |
| 5–8 | 13–16 | Ranking | [[02-ranking]] | 반영 |

## 2. 코드·예제 커버리지
| 원문 예제 | 노트 | 설명 보강 |
|---|---|---|
```

**소유권**: 스킬 소유 — 챕터 시작 시 왼쪽 세 열을 스킬이 채우고, 정리가 진행될
때마다 정리 노트·상태 칸을 갱신한다.

## ⑥ `_glossary.md`

책 전체 단일 용어집. **개념 정의의 유일한 원본**이며 그래프의 concept 노드가
여기서 생성된다. deep-tutor 와 달리 챕터마다 따로 두지 않는다 — 같은 개념이
여러 챕터에 걸쳐 등장하는 것 자체가 그래프의 엣지이므로, 정의가 챕터마다
중복되면 안 된다.

### 무엇을 쓰는가

| 요소 | 형식 |
|---|---|
| 제목 | `## 슬러그 (원어)` — 원어가 없으면 `## 슬러그` 만. 슬러그에 공백 금지(하이픈 연결), `##` 뒤 첫 토큰과 정확히 일치해야 `[[슬러그]]` 링크가 대조된다 |
| 정의 | 제목 다음 줄부터 2~4문장. 최소 한 번은 비전문 언어로 착지한다. 첫 문장은 그래프 뷰어의 개념 정보 패널에 표시된다(빌더가 추출) |
| 처음 나온 곳 | `- 처음 나온 곳: [[노트]]` |
| 섞이는 말 (선택) | `- 섞이는 말: [[슬러그]] — 구분 포인트 한 줄`. 있으면 그래프의 `related` 엣지가 된다 |

**중복 정의 금지** — 같은 용어를 두 번 등재하지 않는다. 다른 노트에서
재등장하면 정의를 복제하지 않고 `[[슬러그]]` 링크만 건다.

### 예시

```markdown
# 용어집

## retrieval (retrieval)
질문과 관련된 문서를 먼저 찾아오는 단계다. 쉽게 말해 도서관 사서가 책부터 뽑아 오는 일이다.
- 처음 나온 곳: [[01-what-is-retrieval]]
- 섞이는 말: [[context]] — retrieval 은 찾는 행위, context 는 찾아온 결과물

## context (context)
모델에 함께 넣어 주는 참고 자료다.
- 처음 나온 곳: [[01-what-is-retrieval]]

## embedding (embedding)
텍스트를 숫자 벡터로 바꾼 표현이다.
```

(마지막 `embedding` 항목처럼 어느 노트에서도 아직 참조되지 않은 용어가 있으면
`build-graph.py` 가 stderr 에 경고를 낸다 — 하드 실패는 아니다.)

**소유권**: 정본 — 개념 정의의 유일한 원본. 절 노트는 정의를 복제하지 않고
`[[_glossary#슬러그]]` 로 링크만 건다.

## ⑦ 구분자 원칙

절 노트와 `_chapter.md` 모두 같은 구분자를 쓴다. 구분자 문자열과 그 위 전체는
**스킬 소유**, 구분자 아래는 **예외 없이 사용자 소유**다.

```markdown
<!-- ==== 아래는 내 메모 · 스킬 수정 금지 ==== -->

## 내 메모
```

스킬은 이 아래를 덮어쓰거나 지우지 않는다 — deep-tutor 와 달리 스킬이 받아 적을
인출 시도·stall 기록이 없으므로(§10 이식 지도, 인출 체계는 이식하지 않는다) 규칙이
더 단순하다: 스킬은 구분자 아래에 **아무것도 쓰지 않는다.** 노트를 보강할 때도
구분자 위만 고친다.

**소유권**: 규칙 그 자체 — 모든 파일에서 구분자 위 = 스킬 소유, 구분자 아래 =
사용자 소유.

## ⑧ 훅 설정 — `.claude/settings.json`

저장소 부트스트랩(온보딩 7단계 중 마지막) 때 사용자가 원하면 스킬이 PostToolUse
훅을 직접 기록한다. **위치는 vault(`{book-slug}-atlas/`) 안이 아니라 그것을 담은
프로젝트 루트다.** 훅 자체는 `matcher: Write|Edit` 로 저장 도구에 걸리고,
`check-note-hook.sh`(Task 8, `<book-atlas-root>/scripts/check-note-hook.sh`)가
대상 판정 후 `check-note.sh` 를 실행해 결과를 피드백한다. deep-tutor 와 달리
Claude Code 전용이라 Codex 분기가 없다.

파일이 이미 있으면 **병합**한다(덮어쓰지 않는다) — 같은 `command` 항목이 있으면
중복 추가하지 않는다.

### 예시

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "$HOME/.claude/skills/book-atlas/scripts/check-note-hook.sh"
          }
        ]
      }
    ]
  }
}
```

`<book-atlas-root>` 는 SKILL.md 의 정의를 따른다 — 설치 후에는
`$HOME/.claude/skills/book-atlas/`, 이 저장소 안에서 실행할 때는
`skills/book-atlas/` (위 예시의 `command` 는 설치 후 기준).

**소유권**: 사용자 소유(프로젝트 설정 파일) — 스킬은 온보딩 때 병합해 넣을 뿐
기존 항목을 덮어쓰지 않는다.
